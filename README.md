# TillBook

TillBook is a web-based hotel and restaurant point-of-sale system for recording food orders, managing the menu, tracking payments, and reviewing daily sales activity.

The application is built with React, TypeScript, TanStack Start, TanStack Router, TanStack Query, Vite, Nitro, Tailwind CSS, and Supabase.

## Features

- Staff authentication with Supabase Auth.
- Staff account registration and sign-in.
- Role-aware access for manager and staff users.
- Dashboard with today's order count, total takings, cash sales, M-Pesa sales, and pending payments.
- New-order workflow with menu categories, quantities, customer/table details, notes, and payment method.
- Cash and M-Pesa payment status tracking.
- Order history with search and filtering.
- Order detail pages for reviewing individual orders.
- Menu management for authorized managers.
- Add, remove, hide/show, and re-price menu items.
- Daily sales summary.
- Responsive interface for desktop and smaller screens.
- Supabase Row Level Security-compatible data access through the Supabase client.

> Payment integration note: the current application records Cash and M-Pesa as payment methods and tracks their payment status. A direct M-Pesa/Daraja transaction API integration is not part of the current application code documented here.

## Application Routes

| Route | Purpose | Access |
| --- | --- | --- |
| `/` | Dashboard and daily overview | Authenticated users |
| `/auth` | Staff sign-in and account creation | Public |
| `/menu` | Menu item management | Managers |
| `/new-order` | Create a food order | Authenticated users |
| `/orders` | Search, filter, and browse orders | Authenticated users |
| `/orders/:id` | View an individual order | Authenticated users |
| `/daily-summary` | Review daily sales activity | Authenticated users |

Routes are defined as `.tsx` files under `src/routes/` and are registered by the generated `src/routeTree.gen.ts` file. Do not edit the generated route tree manually; it is regenerated by the TanStack tooling.

## Supabase Data Model

The current TypeScript database definitions describe these public tables:

### `profiles`

Stores the application profile for a user.

- `id`
- `full_name`
- `job_title`
- `created_at`

### `user_roles`

Stores application roles assigned to users.

- `id`
- `user_id`
- `role`

Current application roles:

- `manager`
- `staff`

### `menu_items`

Stores dishes available to the ordering interface.

- `id`
- `name`
- `category`
- `price`
- `is_available`
- `created_at`

### `orders`

Stores the main order record.

- `id`
- `order_number`
- `customer`
- `table_number`
- `employee_id`
- `employee_name`
- `payment_method`
- `payment_status`
- `order_status`
- `total`
- `notes`
- `approved_at`
- `approved_by`
- `created_at`

### `order_items`

Stores the individual items belonging to an order.

- `id`
- `order_id`
- `name`
- `quantity`
- `price`

`order_items.order_id` references `orders.id`.

## Authentication

Authentication is handled by Supabase Auth.

The client application uses `supabase.auth.signInWithPassword()` for staff sign-in and `supabase.auth.signUp()` for account creation. Sessions are persisted in browser `localStorage` and automatically refreshed by the Supabase client.

Server-side protected operations can use the Supabase authentication middleware in `src/integrations/supabase/auth-middleware.ts`. Administrative server operations can use `supabaseAdmin` from `client.server.ts`, which requires the server-only service-role key.

Never expose `SUPABASE_SERVICE_ROLE_KEY` or any other server secret to browser code.

## Environment Variables

Copy the example file before starting local development:

```bash
cp .env.example .env
```

Configure the following values:

```env
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_your-key

SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_your-key
SUPABASE_SERVICE_ROLE_KEY=your-server-only-service-role-key
```

### Variable usage

- `VITE_SUPABASE_URL`: browser Supabase URL.
- `VITE_SUPABASE_PUBLISHABLE_KEY`: browser-safe Supabase publishable key.
- `SUPABASE_URL`: server-side Supabase URL.
- `SUPABASE_PUBLISHABLE_KEY`: server-side publishable key used by authentication middleware.
- `SUPABASE_SERVICE_ROLE_KEY`: server-only privileged key. Do not commit it or expose it to the client.

Environment files are intentionally ignored by Git. Use `.env.example` as the configuration template.

## Supabase Security Model

The browser uses the publishable Supabase key. This key is designed for client-side use when Row Level Security policies are correctly configured.

Privileged database access must remain server-side. The service-role key bypasses RLS and must only be loaded by trusted server code.

Recommended production controls:

1. Enable Row Level Security on application tables.
2. Allow authenticated staff to read and create only the records required for their work.
3. Restrict menu administration to manager users.
4. Keep service-role credentials outside source control.
5. Use separate development and production Supabase projects when appropriate.
6. Review authentication redirect URLs in the Supabase dashboard before production deployment.

## Order Workflow

The current order flow is:

1. Staff opens **New Order**.
2. Menu items are loaded from `menu_items`.
3. Staff selects quantities and enters the customer/table information.
4. Staff selects Cash or M-Pesa.
5. Cash orders are recorded as `PAID`.
6. M-Pesa orders are recorded as `PENDING` until the application's payment approval flow changes their status.
7. The order and its line items are stored in `orders` and `order_items`.
8. The user is redirected to the order detail page.

## Menu Management

Managers can manage menu items from `/menu`.

Supported operations include:

- Add a dish.
- Select a category.
- Set a price.
- Change a price.
- Hide an item from staff ordering.
- Show a hidden item.
- Remove an item.

The default categories currently used by the interface are:

- Breakfast
- Main meals
- Sides
- Drinks

Additional categories already stored in the database are also displayed.

## State Management

TanStack Query manages server data and caching. Typical query keys include:

- `orders`
- `menu_items`

Mutations invalidate the relevant query so changes become visible without requiring a full page reload.

## Code Conventions

- Keep route-specific UI in `src/routes/`.
- Put reusable application components in `src/components/`.
- Put reusable hooks in `src/hooks/`.
- Keep Supabase integration code under `src/integrations/supabase/`.
- Keep shared POS types and formatting helpers under `src/lib/`.
- Use TypeScript types generated or maintained from the Supabase database schema.
- Do not edit `src/routeTree.gen.ts` manually.
- Keep privileged Supabase operations in server-only modules.

For Cloudflare Workers, the current TanStack Start documentation recommends the Cloudflare Vite plugin and Wrangler configuration. See the official TanStack Start hosting documentation for the target-specific setup.

## Database and Migrations

Database changes should be made in the Supabase project and reflected in the application's generated TypeScript database definitions. The repository also contains Drizzle configuration and migration artifacts, but the current application routes use Supabase directly for application data access.

When changing the database schema:

1. Apply the schema change in the target database.
2. Update the generated/maintained Supabase TypeScript definitions.
3. Update affected routes, hooks, or server functions.
4. Test authentication and RLS behavior.
5. Run the production build before deployment.

## Troubleshooting

### Missing Supabase environment variables

If the application reports missing Supabase configuration, check both browser and server variables and restart the development server after changing `.env`.

### Authentication failures

Verify:

- The Supabase URL is correct.
- The publishable key belongs to the same Supabase project.
- Email/password authentication is enabled in Supabase.
- The application's redirect URL is allowed by Supabase Auth.
- The browser is not using stale build-time environment values.

### Orders or menu items do not load

Check the browser console and Supabase logs. Then verify that the relevant table exists, the client is connected to the intended project, and RLS policies allow the authenticated user to perform the requested operation.
